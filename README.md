## ◆ &nbsp;What I turned down

> [!TIP]
> The rejected column is the actual work. Every row shipped to production.

| Context | ❌ Rejected | ✅ Shipped | Why |
|:---|:---|:---|:---|
| **Agentic skill catalog** | Kubernetes | GCP Cloud Run | Right runtime for a dedicated platform crew. There wasn't one — a cluster would have pulled the team off shipping. |
| **Medusa seller portal** | Another Medusa release<br/>Greenfield rewrite | Decompose onto the existing platform | The framework was the bottleneck. A rewrite discards a platform that already worked. |
| **Gaming platform** | Lift-and-shift<br/>Managed PaaS | EKS with GitOps delivery | PaaS started faster and gave up the secrets, artifact and release control the product needed. |
| **Loyalty modernization** | Rehost-only<br/>Full rewrite | Modular IaC, modernize per workload | Rehost kills the business case. A rewrite misses committed cutover dates. |
| **56 regulated services** | Per-team pipelines<br/>One central pipeline | Golden paths with self-service | Autonomy leaves no evidence trail; centralization makes one change queue for 56 services. |

## ◆ &nbsp;What experience actually taught me

> [!IMPORTANT]
> The failure mode on a new product is over-engineering it before anyone uses it.
> Ship the production path, then let real usage decide the next layer.

- **A framework can look modular and still be the bottleneck.** The leverage wasn't rewriting the portal myself — it was making the platform fast enough that 30 developers could.
- **Enablement is part of the platform.** Reusable modules only reduced drift once teams understood the reasoning behind them.
- **Compliance automation is an accelerator, not a tax.** Once controls ran in the pipeline, approvals moved from debate to evidence.
- **Discovery workshops are architecture work.** Explicit standards early prevent the requirement churn that eats a four-month window.
